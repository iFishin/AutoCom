# AutoCom 流水线错误参考

## E001：设备名不匹配

- **严重度**：blocker（阻塞）
- **现象**：步骤引用了不存在的设备
- **常见原因**：`Steps[*].device` 拼写错误
- **修复**：确保每个 `Steps[*].device` 匹配某个 `Devices[*].name`

## E002：`type` 缺失或无效

- **严重度**：blocker（阻塞）
- **现象**：步骤无法执行
- **常见原因**：`type` 字段缺失或拼写错误
- **修复**：必须是以下之一：`serial`, `serial_wait`, `http`, `script`, `wait`, `action_batch`, `goto`

## E003：`expect` 缺失或太宽松

- **严重度**：major（主要）
- **现象**：步骤在收到垃圾数据时也通过；成功/失败状态错误
- **常见原因**：未指定 `expect`，或匹配范围太宽
- **修复**：始终将 expect 设置为设备成功时返回的唯一关键字（例如 `["OK"]`）

## E004：超时时间太小

- **严重度**：major（主要）
- **现象**：高延迟操作（连接、扫描、OTA、重启）持续超时
- **常见原因**：对慢速操作使用了默认 3-5 秒超时
- **修复**：增加 `timeout`（秒）。WiFi 连接：15-30s，OTA：30-60s，重启：10-30s

## E005：`capture` 正则不匹配

- **严重度**：major（主要）
- **现象**：捕获变量为空/null
- **常见原因**：正则太严格、YAML 中未双重转义、或设备输出格式已更改
- **修复**：针对实际设备输出测试正则。YAML 中使用 `\\d+` 而非 `\d+`

## E006：变量未定义

- **严重度**：blocker（阻塞）
- **现象**：步骤引用了不存在的变量
- **常见原因**：`{VAR}` 没有对应的 `Constants.KEY`，或 `{{ steps.ID.capture.KEY }}` 中的步骤 ID 错误
- **修复**：定义常量或检查步骤 ID 拼写

## E007：`on_error` / `on_success` 语法错误

- **严重度**：major（主要）
- **现象**：错误处理未按预期工作
- **常见原因**：使用 `retry: 3`（旧格式）而非 `retry(3)`，或拼写错误 `goto`
- **修复**：使用 `retry(N)`、`goto(id)`、`skip`、`abort`（字符串，非对象）

## E008：`goto` 目标无效

- **严重度**：blocker（阻塞）
- **现象**：运行时错误"goto target not found"
- **常见原因**：目标步骤 ID 不存在或拼写错误
- **修复**：验证 `target`（在 `goto` 步骤中）或 `goto(id)`（在 `on_error` 中）引用了已存在的 `id`

## E009：循环配置误用

- **严重度**：minor（次要）
- **现象**：循环永不终止，或意外循环
- **常见原因**：将循环逻辑放在流水线配置中而无 CLI 限制
- **修复**：使用 CLI `-n N` / `--duration 30s` 而非在配置中硬编码迭代次数

## E010：`if`/`unless` 条件语法

- **严重度**：major（主要）
- **现象**：条件始终评估为 false（或 true）
- **常见原因**：运算符错误或模板语法错误
- **修复**：使用 `==`、`!=`、`>=`、`<=`、`>`、`<`。引用：`{{ steps.X.capture.Y | int }}`

## E011：并发状态损坏

- **严重度**：major（主要）
- **现象**：并行 HTTP 步骤偶发失败
- **常见原因**：步骤共享可变上下文或在设备访问上存在竞争
- **修复**：确保并行步骤独立；如果共享状态则使用顺序执行

## E012：`serial_wait` 缺少 `device`

- **严重度**：blocker（阻塞）
- **现象**：步骤无任何操作
- **常见原因**：缺少 `device` 字段
- **修复**：`serial_wait` 需要 `device` 引用来监听

## E013：Steps 列表为空

- **严重度**：blocker（阻塞）
- **现象**：流水线运行但无任何操作
- **常见原因**：未定义步骤
- **修复**：至少添加一个步骤

## E014：过时的 `$VAR` 语法

- **严重度**：minor（次要）
- **现象**：变量未解析
- **常见原因**：使用 `$SSID` 而非 `{SSID}`
- **修复**：将所有字段中的 `$VAR` 替换为 `{VAR}`
